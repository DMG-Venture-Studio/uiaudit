# capture-one-cell

Acceptance: Fili, with voice-resume's dev server running on the Mac, runs uiaudit for one route, one state and one viewport, sees that cell's screenshot in the run folder and a summary with the cell count and what was checked, stops the dev server, runs it again and gets an environment error that names the command to fix it, and can say: "I ran uiaudit against voice-resume, saw the cell's screenshot and summary, and a broken app failed loudly with the fix instead of passing."

- [ ] Kernel: `errors.py` gives `Invalid`, `Refused` and `Unreachable` a `kind` from one closed set (`invalid`, `refused`, `environment`, plus `internal` for an unexpected exception) and an exit code (2, 2, 3, and 4 for `internal` until the `internal-exit-code` question below is decided), each carrying `next_step`, the exact command or action that fixes it, written as fields and values (`state=default`), never as one surface's flags; `envelope.py` gains `kind`, `code` and `summary: str | None`. `ids.py`: a run id from the clock, `YYYYMMDDTHHMMSSZ`. `clock.py`: `now()` in UTC; code reads it as `clock.now()` through the module and tests monkeypatch `uiaudit.kernel.clock.now`. `resources.py`: `Browser` gets `status(url) -> int | None` and `capture(url, viewport_width, theme) -> Capture` (PNG bytes, final URL, the main document's status); `Engine(version, sha, dirty)`; `Resources` has `engine: Engine`, always handed in, and `browser: Browser | None`; the catalog hands an operation `dataclasses.replace(resources, ...)` with only the browser it names, and an operation whose browser is None refuses `internal`. The parity test asserts every `Operation.resources` name is a field of `Resources`. `principals.py`: `operator`, `agent` and `ci` each hold `run.start`; no principal holds a triage grant.

Never `importlib.metadata` (the ways-in check refuses it).
- [ ] environment noun: `model.Environment` (name, base_url, mocks, optional health_path such as `/api/me` where 401 still means up), `model.Config`, and `model.EnvironmentCheck(env: str)`, the request `run_start` builds from `request.env` (environment never imports run); `rules.parse_config(text, env_name)` is pure and holds one closed key list per table: top level `requires, fail_on, viewports, themes, routes, design, env`, and `[env.*]` `base_url, mocks, health_path, source_stamps, read_only`; it refuses with `Invalid` a TOML parse error naming the line, an unknown key naming the key and the allowed keys, an environment name other than `local` or `staging`, a missing `[env.<name>]`, a missing `base_url`; `rules.reachable(status)`: None is down; 2xx, 3xx, 401 and 403 are up; anything else is down, including the 5xx Vite's proxy returns when the API is stopped; `ops.environment_check(request: EnvironmentCheck, resources)` reads `uiaudit.toml` from the working directory (missing is `Invalid`, next step: write it with `[env.local] base_url = ...`), probes `base_url` and `health_path` through `Browser.status`, refuses `Unreachable` with next step "start the dev server at <url>, then re-run" naming the first URL that is down, and returns the envelope with the base URL and the statuses. It is a function `run.ops` calls in this gate; whether it also enters the catalog as its own operation is the `environment-check-exposure` question below. No sign-in key in this gate: loading a sign-in file and refusing a git-tracked one arrive together with sign-in.

Tried to break (the red lane attempts at least these):
- Stop the dev server before a run: exit 3, the next step names the URL to start.
- Stop the dev server during a run, between the environment check and the capture: a manifest on disk with the cell error, cells captured 0, exit 3; never a clean summary.
- Point the config at a route that does not exist: on voice-resume it redirects to `/`, so the run is refused naming where the route ended and both fixes; a non-2xx document status is refused naming the status.
- Use an expired or missing sign-in: a route that redirects away from itself is refused as `Unreachable` naming where it ended; sign-in files themselves arrive with the full matrix.
- Make the state setup throw: a state other than `default` is refused as `Invalid` with the next step; the throwing state itself is carried to the full-matrix gate (see the question below).
- Run twice on an unchanged UI: two manifests, both one planned, one captured, `checks` empty; two runs in the same second do not overwrite each other.
- Remove the browser from the tool environment: exit 3 and a next step that works from the audited repository's directory, not only from the uiaudit checkout.
- Malformed inputs: a viewport of 0 or 100000 or `abc`, a theme of `Light`, a route without a leading slash, `//evil.example`, `/../x`, an env name not in the config or not `local`/`staging`, a `uiaudit.toml` that does not parse or holds a misspelled key, `.uiaudit/runs` that is a file, a missing or extra argument key in a direct catalog call: each exit 2 with a next step, never a traceback, the same envelope on every surface.
- A broken neighbour beside a valid one: two `[env.*]` tables, one with no base_url; the valid one succeeds, the broken one exits 2 naming the key.
- Out of order: `run start` without any separate check still checks the environment itself.
- The API down but the Vite server up: `health_path` catches it; exit 3 names the health URL.
- Call `run_start` over HTTP and over MCP with the real browser: a capture, never Playwright's "sync API inside the asyncio loop" error.
- Run the demo command without `--json`: a readable summary naming the PNG, not raw JSON.
- The owner's break step: stop the dev server and run the command again; it must exit with an environment error that names the command to fix it, never a clean summary.
